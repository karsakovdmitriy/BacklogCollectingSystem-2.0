# Руководство по развертыванию (Deployment Guide)

Данное руководство содержит пошаговую инструкцию по развертыванию MVP "Системы сквозной продуктовой аналитики и управления релизами" с использованием **Supabase** в качестве базы данных, **Next.js (App Router)** для фронтенда и бэкенд-серверов, и платформы **Vercel** для хостинга.

---

## Шаг 1: Развертывание базы данных на Supabase

1. Перейдите на сайт [Supabase](https://supabase.com/) и войдите под своей учетной записью (или зарегистрируйтесь).
2. Нажмите **"New Project"** (Новый проект) и введите параметры:
   - **Name:** `Product-Cockpit-MVP`
   - **Database Password:** Сгенерируйте и обязательно сохраните надежный пароль.
   - **Region:** Выберите ближайший к вашим пользователям регион (например, *Frankfurt* для Европы).
3. Дождитесь завершения инициализации базы данных (обычно занимает 1–2 минуты).
4. Перейдите в раздел **SQL Editor** (редактор SQL) в левом меню панели Supabase.
5. Нажмите **"New query"** (Новый запрос).
6. Скопируйте полностью содержимое файла `schema.sql` из корня данного репозитория и вставьте его в текстовое поле SQL-редактора Supabase.
7. Нажмите кнопку **"Run"** в правом нижнем углу для выполнения скрипта.
   - Скрипт создаст все необходимые таблицы (`epics`, `initiatives`, `requests`, `features`, `tasks`, `releases`, `pm_audits`), индексы, пользовательские типы ENUM и настроит базовую безопасность Row Level Security (RLS).

---

## Шаг 2: Получение API ключей Supabase

1. Перейдите в раздел **Project Settings** (Настройки проекта, иконка шестеренки внизу слева) -> **API**.
2. Скопируйте следующие значения, они понадобятся для настройки переменных окружения:
   - **Project URL:** `https://your-project-ref.supabase.co` (это будет `NEXT_PUBLIC_SUPABASE_URL`)
   - **API Keys (anon public):** Ключ общего доступа (это будет `NEXT_PUBLIC_SUPABASE_ANON_KEY`)

---

## Шаг 3: Переход от LocalStorage к интеграции с Supabase (Опционально)

Текущий MVP использует реактивный хук `useProductState` с персистентным хранением в `localStorage` для мгновенной автономной демонстрации.
Для полноценного продакшн-подключения к Supabase выполните следующие шаги в коде:

1. Установите клиент Supabase JS:
   ```bash
   bun add @supabase/supabase-js
   ```
2. Создайте файл конфигурации `src/lib/supabaseClient.ts`:
   ```typescript
   import { createClient } from '@supabase/supabase-js';

   const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL || '';
   const supabaseAnonKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY || '';

   export const supabase = createClient(supabaseUrl, supabaseAnonKey);
   ```
3. Модифицируйте `src/store/useProductState.ts` для асинхронного выполнения запросов `select`, `insert`, `update` и `delete` к соответствующим таблицам вместо работы с локальным массивом.

## Шаг 4: Развертывание приложения на Vercel

### Вариант А: Развертывание через интерфейс Vercel (Рекомендуется)

1. Закоммитьте и отправьте ваш код в Git-репозиторий (GitHub, GitLab или Bitbucket).
2. Зарегистрируйтесь или войдите в панель управления [Vercel](https://vercel.com/).
3. Нажмите кнопку **"Add New..."** и выберите **"Project"**.
4. Импортируйте ваш репозиторий с проектом.
5. В секции **Configure Project** настройте следующее:
   - **Framework Preset:** Next.js
   - **Root Directory:** `./`
   - **Build and Output Settings:** Оставьте по умолчанию (`next build`).
6. Раскройте секцию **Environment Variables** (Переменные окружения) и добавьте переменные, полученные на *Шаге 2*:
   - `NEXT_PUBLIC_SUPABASE_URL` = `<Ваш_Supabase_URL>`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = `<Ваш_Supabase_Anon_Key>`
7. Нажмите кнопку **"Deploy"**. Процесс компиляции займет около 1-2 минут, после чего приложение будет доступно по публичному адресу `https://<your-project-name>.vercel.app`.

---

### Вариант Б: Развертывание через Vercel CLI (Для терминала)

Если вы предпочитаете деплой непосредственно из командной строки:

1. Установите Vercel CLI глобально или запустите через `npx`:
   ```bash
   npm install -g vercel
   ```
2. Выполните команду авторизации и инициализации в корне папки проекта:
   ```bash
   vercel login
   ```
3. Запустите первоначальную привязку проекта:
   ```bash
   vercel link
   ```
4. Добавьте переменные окружения в проект Vercel:
   ```bash
   vercel env add NEXT_PUBLIC_SUPABASE_URL <Ваш_Supabase_URL>
   vercel env add NEXT_PUBLIC_SUPABASE_ANON_KEY <Ваш_Supabase_Anon_Key>
   ```
5. Сделайте итоговую сборку и деплой на продакшн:
   ```bash
   vercel --prod
   ```

## Шаг 5: Проверка и тестирование релиза

После завершения деплоя на Vercel:
1. Перейдите по предоставленной Vercel-ссылке.
2. Проверьте полную интерактивность интерфейса:
   - Создайте новую фичу/таск.
   - Проведите ручной PM-апгрейд приоритета фичи и заполните причину аудита (убедитесь, что плашка сравнения и лог внизу обновились).
   - В разделе **Конструктор Релиза** используйте ползунок Capacity и протестируйте авто-подбор фич по алгоритму рюкзака (Knapsack).
   - Нажмите "Утвердить Релиз" и проверьте логи экспорта в GitLab во встроенном терминале.
   - Ознакомьтесь с ROI-дашбордом и диаграммами распределения затрат по Эпикам.
